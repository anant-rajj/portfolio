VeriPack

Package vs Source Integrity Analyzer

Modern package registries (npm, PyPI) allow published tarballs to contain files and build artifacts never committed to upstream Git repositories. VeriPack ingests distributed tarballs, enforces strict path-boundary sanitization against Zip-Slip attacks (CVE-2018-1002204), and computes byte-for-byte provenance differentials against upstream Git trees.

mac-insomnia

Lid-Closed Execution Engine for Apple Silicon

Most stay-awake utilities consume 50–100 MB of resident RAM, inject background electron runtimes, or require an external monitor attached. mac-insomnia is an ultra-lightweight native CLI engineered with Apple's low-level IOKit power management assertions to allow MacBooks to execute long-running AI pipelines, local LLM inference (Ollama, llama.cpp), and compilations with the lid closed.

RESOURCE RESIDENCE: < 8 MB active RAM • 0 MB idle resident (on-demand CLI)
CORE PRIMITIVES: IOKit • IOPMAssertionCreateWithName • Battery Threshold Cutoff
MY CONTRIBUTION: Complete system design, IOKit assertion harness, safety battery-floor guard
STATUS: Open Source • Tested on M-Series Architecture

CHAPTER 06 // CADENCE & ORIGIN FROM THE TRACK TO THE KERNEL

Cadence Over Chaos. Discipline Over Momentum.

The foundation of my work: why competitive track athletics forged my mindset as a systems builder.

Before I ever analyzed a software supply chain or interfaced with an Apple Silicon power assertion, my life was governed by the track.

I competed in 100-meter and 200-meter sprints and endured long-distance marathons. On the track, there is nowhere to hide. You learn quickly that velocity is not created by frantic flailing; it is the result of strict cadence, stride economics, breath control, and the disciplined willingness to stay completely composed through the burning fatigue of the final 40 meters.

When I shifted my focus during intensive JEE preparation and entered engineering at Rishihood University, I carried that exact athletic cadence directly into computer systems.

I don't treat code as a cosmetic hobby or a checklist for a resume. When a system breaks or a build fails, I approach it the way an athlete reviews split-times: isolate the constraint, eliminate the parasitic friction, test repeatedly against hard reality, and build solutions that endure.

// ATHLETIC HEURISTIC

“Form under fatigue reveals whether you actually understand the discipline.”

CORE OPERATING PRINCIPLES

01 Deconstruct Before Coding

Investigate the ecosystem deeply. Understand the historical constraints and memory layouts before opening an editor.

02 Zero Parasitic Abstractions

03 Deterministic Verification

04 Critique as Engineering Signal

Treat jury reviews and failed runs as high-signal input. Strip away ego and rebuild until the architecture is bulletproof.
